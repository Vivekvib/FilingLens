# Slim requirements for the RENDER deployment specifically — NOT the same
# as the root requirements.txt used for local development.
#
# /companies, /risk-memo, and /consistency only read cached JSON files and
# never touch any fetching or embedding stack.
#
# POST /analyze (the on-demand "analyze any company" feature) DOES need
# real SEC fetching (requests, beautifulsoup4) and retrieval (scikit-learn
# for TF-IDF) — but deliberately NOT sentence-transformers/chromadb/torch.
# Those were the actual cause of the earlier Render OOM crash (PyTorch's
# default Linux wheel bundles the full CUDA toolkit, several GB, unneeded
# on a CPU-only free tier) — scikit-learn has no such baggage, it's a
# lightweight, CPU-native library. See src/ondemand/tfidf_retriever.py's
# docstring for the full reasoning behind this split.
#
# /query (the OTHER live endpoint, for the 8 pre-baked companies) still
# needs the full sentence-transformers/chromadb stack and is NOT
# installed here — it gracefully returns a 503 in production (see the
# try/except in src/api/main.py's ad_hoc_query). Run locally with the
# full requirements.txt to use /query and to run the batch pipeline.
